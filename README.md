# Minecraft Bot

Mineflayer-бот с ручным управлением через чат. Текущий этап — команды для core abilities: навигации, инвентаря, добычи и простого крафта. Автономность пока не реализована.

## Запуск

Требуется Node.js с поддержкой ESM и `node --test`.

```sh
npm ci
npm start
```

Настройки берутся из `.env`: `MC_HOST` (по умолчанию `127.0.0.1`), `MC_PORT` (`25565`), `MC_USERNAME` (`AnenBot`), `MC_AUTH` (`offline`), `BOT_PREFIX` (`!`). Для Microsoft-аутентификации задайте `MC_AUTH=microsoft`. `OWNER_NAME` пока не ограничивает доступ к командам: ими могут пользоваться игроки в чате.

## Команды

В примерах используется стандартный префикс `!`.

| Команда | Действие |
| --- | --- |
| `!help` | Список команд |
| `!goto` | Перейти к текущей позиции вызвавшего игрока |
| `!goto Steve` | Перейти к текущей позиции видимого игрока |
| `!goto 10 64 -20` | Перейти к координатам |
| `!follow [player]` | Следовать за игроком; по умолчанию за вызвавшим команду |
| `!stop` | Остановить навигацию, сбор блоков и движение |
| `!inventory` | Показать содержимое инвентаря |
| `!chop` | Найти ближайшие обычные брёвна и собрать связанные блоки |
| `!mine <block> [count]` | Добыть указанное число ближайших блоков |
| `!equip <item> [destination]` | Экипировать предмет из инвентаря |
| `!craft <item> [count]` | Скрафтить указанное количество предметов из имеющихся ресурсов |

Используйте внутренние имена Minecraft, например `oak_log`, `cobblestone`, `wooden_pickaxe`. Количество — положительное целое число, по умолчанию `1`. Для экипировки доступны `hand` (по умолчанию), `off-hand`, `head`, `torso`, `legs`, `feet`.

Крафт не добывает ресурсы и не строит верстак. Для рецептов 3×3 нужен уже существующий доступный верстак рядом. Количество означает число выходных предметов; если рецепт выдаёт несколько предметов, результат округляется вверх до целого числа операций крафта. Добыча ограничена ближайшей областью и зависит от доступного инструмента и пути. `!chop` собирает до 64 связанных брёвен, а не определяет полную геометрию дерева.

`!stop` очищает цели сбора и навигации, прерывает уже начатое копание и сбрасывает управление. У используемого `collectblock` есть ограничения отмены: ожидающая экипировка может завершиться последним копанием, а ожидание подбора предмета может оставаться незавершённым внутри плагина. Команда остановки не ждёт такого ожидания бесконечно. Для нового действия после добычи сначала используйте `!stop`; полноценное согласование параллельных действий отложено.

## Текущая архитектура

```text
User → Command → Service → Mineflayer
```

**Commands** (`src/commands/`) — пользовательский интерфейс: parsing, validation, routing и output. Здесь остаются перегрузки `goto`, выбор имени игрока, проверка синтаксиса и ответы в чат.

**Services** (`src/services/`) — core abilities: Minecraft API, Goals, поиск и сбор блоков, инвентарь, экипировка и крафт. Они не разбирают чат и не отправляют сообщения пользователю. Команды импортируют сервисы напрямую; `CommandManager` передаёт только `{ bot, username, args }`.

Сервисы получают актуальный `bot` при каждом вызове, поэтому не удерживают старый экземпляр после reconnect:

```js
import NavigationService from './src/services/NavigationService.js'

await NavigationService.goto(bot, 100, 64, 200)
```

Активные API: `NavigationService.goto/follow/stop`, `InventoryService.list/equip`, `MiningService.chopTree/mine`, `CraftingService.craft`. Результаты операций содержат `status`; ожидаемые ошибки выполнения и прерывания нормализуются в сервисах. Неожиданные ошибки навигации передаются вызывающему коду. Форматирование результата остаётся в команде.

Существующие `core/`, `plugins/`, `behaviors/`, `utils/` и `MemoryService` сохранены. Заготовки behaviors/plugins не означают реализованную автономность. Tasks, TaskManager, Planner и autonomous behavior будут добавляться позже поверх Service API; они не участвуют в текущем выполнении команд.
